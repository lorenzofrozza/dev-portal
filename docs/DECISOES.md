# Registro de decisões técnicas

Formato: data — decisão — alternativas consideradas — motivo. Este arquivo alimenta o artigo final (seção de desenvolvimento). Registrar aqui toda escolha não óbvia feita durante os ciclos.

- 2026-10-02 — **Tailwind v4 compilado no build** em vez de CSS puro com tokens — alternativas: CSS puro (zero dependências), Tailwind via CDN (descartado: viola a regra de runtime sem terceiros) — motivo: velocidade de desenvolvimento nos ciclos; a dependência é só de build (devDependency), o artefato final continua estático e auto-hospedado.
- 2026-10-02 — **Light DOM nos custom elements** — alternativa: Shadow DOM com CSS próprio por componente — motivo: classes utilitárias do Tailwind não atravessam shadow root; o encapsulamento visual não é requisito e o isolamento lógico se mantém por convenção (um arquivo por componente).
- 2026-10-02 — **Hash routing** — alternativa: History API — motivo: funciona no GitHub Pages e offline sem configuração de fallback de rotas no servidor.
- 2026-10-02 — **Fontes do sistema** (`system-ui`) — alternativa: fonte própria auto-hospedada — motivo: zero requisições extras e carga menor; revisar no ciclo 5 se a identidade visual pedir fonte própria.
- 2026-11-15 — **Aleatoriedade do gerador CPF/CNPJ via `crypto.getRandomValues`**, descartando bytes 250–255 — alternativa: `Math.random()` — motivo: API nativa (sem rede) com distribuição uniforme; o descarte evita que `byte % 10` favoreça os dígitos 0–5 (conferido: 5.000 CPFs, cada dígito entre 9,7% e 10,4%).
- 2026-11-15 — **CNPJ gerado sempre com filial 0001 (matriz)** — alternativa: filial aleatória — motivo: é o formato mais comum em cadastros de teste; os 8 dígitos da raiz continuam aleatórios.
- 2026-11-15 — **CPF com todos os dígitos iguais é descartado na geração e recusado na validação** — motivo: sequências como 111.111.111-11 passam no cálculo do DV, mas sistemas reais as rejeitam; gerá-las produziria dado de teste inútil.
- 2026-11-15 — **Histórico do gerador no escopo do módulo, não no componente nem no `localStorage`** — alternativa: guardar no elemento (perde ao trocar de ferramenta) ou em `localStorage` (persiste conteúdo gerado, contra a regra 5) — motivo: sobrevive à navegação entre ferramentas e some ao recarregar a página, que é a definição de "sessão" do RF09. Lista única com CPF e CNPJ marcados, máximo de 10.
- 2026-11-15 — **Validador sem `<form>`** (botão + Enter no campo) — motivo: um `<form>` pode virar submit e levar o conteúdo digitado na URL se o JavaScript falhar; sem ele, não existe caminho de rede para o dado, o que é mais fácil de defender na inspeção.
- 2026-11-15 — **Cópia com alternativa via `execCommand('copy')`** quando a Clipboard API é negada — motivo: navegadores embutidos e WebViews bloqueiam `navigator.clipboard`; a alternativa é local e mantém o RF09 funcionando nesses ambientes.
- 2026-11-15 — **CNPJ alfanumérico não suportado nesta versão**: o validador detecta letras e avisa — motivo: escopo fechado em 4 ferramentas; o novo formato da Receita fica no backlog (REQUISITOS.md), mas a entrada não é tratada como erro genérico.
